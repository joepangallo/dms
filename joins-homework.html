Guided lesson

How joins work

A join places columns from related rows side by side. Every join needs two decisions: which rows should be preserved, and which columns prove that two rows match.

Join Types at a Glance: INNER JOIN, LEFT JOIN, and RIGHT JOIN
Join Type Which Rows Survive? Handling of Unmatched Rows Common Use Case
INNER JOIN Only rows matching in BOTH tables Unmatched rows from either side are excluded Show completed pairs (e.g. students enrolled in courses)
LEFT JOIN ALL rows from the Left table (first table) Right-side columns are filled with NULL when missing Show master lists (e.g. all students regardless of enrollment)
RIGHT JOIN ALL rows from the Right table (second table) Left-side columns are filled with NULL when missing Show target master lists (Equivalent to swapping tables in a LEFT JOIN)
1

Start with an INNER JOIN

An inner join keeps only pairs for which the ON condition is true. Rows without a partner disappear.

Example 1 · Match students to enrollment rows
SELECT s.student_id,
       s.first_name,
       s.last_name,
       e.course_id
FROM STUDENT AS s
INNER JOIN ENROLLMENT AS e
    ON s.student_id = e.student_id
ORDER BY s.student_id, e.course_id;

Read it line by line

  1. SELECT chooses the columns to display.
  2. FROM STUDENT AS s chooses the starting table and nickname s.
  3. INNER JOIN ENROLLMENT AS e names the second table.
  4. ON compares the related key columns.
  5. ORDER BY sorts the finished result; it does not control matching.
10 rows: one per enrollment
S101 appears twice because Alina has two enrollments.
S107 is absent because Maya has no matching enrollment.
INNER JOIN template
SELECT columns_to_display
FROM first_table AS a
INNER JOIN second_table AS b
    ON a.shared_key = b.shared_key;
2

Connect three tables one hop at a time

STUDENT does not contain a course name. Walk through ENROLLMENT to reach COURSE, adding one join for each link.

Example 2 · Student names, course names, and grades
SELECT s.first_name,
       s.last_name,
       c.course_name,
       e.final_grade
FROM STUDENT AS s
INNER JOIN ENROLLMENT AS e
    ON s.student_id = e.student_id
INNER JOIN COURSE AS c
    ON e.course_id = c.course_id
ORDER BY c.course_name, s.last_name;

Follow the path

  • First link: STUDENT → ENROLLMENT on student_id.
  • Second link: ENROLLMENT → COURSE on course_id.
  • Three tables require two join links. In a simple chain, N tables need N − 1 joins.
  • Qualify every selected column with its alias so the source stays clear.
Still 10 rows: course names were added to the ten enrollment rows.
3

Add a filter after the joins

ON says how tables relate. WHERE says which of those matched rows the question wants.

Example 3 · Only Database Foundations enrollments
SELECT s.first_name,
       s.last_name,
       e.final_grade
FROM STUDENT AS s
INNER JOIN ENROLLMENT AS e
    ON s.student_id = e.student_id
WHERE e.course_id = 'CIS101'
ORDER BY s.last_name;

Do not mix up ON and WHERE

  • ON s.student_id = e.student_id is the relationship. Removing it creates unrelated pairings.
  • WHERE e.course_id = 'CIS101' is a business filter. Removing it keeps all valid enrollments.
  • Text values use single quotes.
3 rows: Alina, Mateo, and Nia.
4

Use LEFT JOIN when every left-side row must survive

A left join keeps every row from the table written before LEFT JOIN. When no match exists, columns from the right table contain NULL.

Example 4 · Keep all students, even those with no course
SELECT s.student_id,
       s.first_name,
       s.last_name,
       e.course_id
FROM STUDENT AS s
LEFT JOIN ENROLLMENT AS e
    ON s.student_id = e.student_id
ORDER BY s.student_id, e.course_id;

Why “left” matters

  • STUDENT is on the left, so all seven students are protected.
  • Students with several enrollments still produce several rows.
  • Maya has no match, so SQLite creates one result row with NULL for e.course_id.
  • Reverse the tables and you protect enrollments instead—not students.
11 rows: ten matches plus one unmatched student.

5

Find only the rows with no match

First preserve unmatched rows with LEFT JOIN. Then keep only the manufactured NULL rows with WHERE ... IS NULL.

Example 5 · Find students with no enrollment
SELECT s.student_id,
       s.first_name,
       s.last_name
FROM STUDENT AS s
LEFT JOIN ENROLLMENT AS e
    ON s.student_id = e.student_id
WHERE e.student_id IS NULL;

The two-step pattern

  1. LEFT JOIN keeps Maya and gives her empty enrollment columns.
  2. WHERE e.student_id IS NULL removes every student who did match.
Never write = NULLNULL means “missing/unknown,” so SQL tests it with IS NULL or IS NOT NULL.
1 row: S107, Maya Chen.
6

Count matches while keeping zero

Combine LEFT JOIN, COUNT, and GROUP BY when categories with no matching rows must still appear.

Example 6 · Count courses taught by every faculty member
SELECT f.faculty_id,
       f.faculty_name,
       COUNT(c.course_id) AS course_count
FROM FACULTY AS f
LEFT JOIN COURSE AS c
    ON f.faculty_id = c.faculty_id
GROUP BY f.faculty_id, f.faculty_name
ORDER BY f.faculty_id;

Why this counts zero correctly

  • FACULTY is left, so all four faculty members survive.
  • COUNT(c.course_id) counts only non-NULL matched course IDs.
  • F40's unmatched row has a NULL course ID, so Daniel Reed's count is 0.
  • COUNT(*) would count that placeholder row and incorrectly show 1.
4 rows: one per faculty member, including F40 with 0.
7

Recognize the older inner-join spelling

If you previously saw tables separated by commas, the matching idea is the same. The explicit JOIN ... ON spelling makes the relationship easier to see.

Older comma-and-WHERE style
SELECT s.student_id, e.course_id
FROM STUDENT s, ENROLLMENT e
WHERE s.student_id = e.student_id;
＝
Explicit INNER JOIN style
SELECT s.student_id, e.course_id
FROM STUDENT s
INNER JOIN ENROLLMENT e
  ON s.student_id = e.student_id;
For this homework, use the explicit styleIt keeps join conditions in ON and leaves WHERE for filters. Also, the word INNER is optional: JOIN by itself means INNER JOIN.
8

Understand RIGHT JOIN and SQLite equivalence

A RIGHT JOIN preserves all rows from the right-side table. SQLite does not support the RIGHT JOIN keyword directly, but you can write any RIGHT JOIN by swapping table order and using LEFT JOIN.

Standard SQL RIGHT JOIN
SELECT c.course_id, c.course_name, e.student_id
FROM ENROLLMENT AS e
RIGHT JOIN COURSE AS c
    ON e.course_id = c.course_id;
＝
SQLite equivalent (Swap tables + LEFT JOIN)
SELECT c.course_id, c.course_name, e.student_id
FROM COURSE AS c
LEFT JOIN ENROLLMENT AS e
    ON c.course_id = e.course_id;
Key Rule: A RIGHT JOIN B produces the exact same output as B LEFT JOIN A. To solve right-join tasks in SQLite, place the table whose rows must all survive first in your FROM clause and use LEFT JOIN.
