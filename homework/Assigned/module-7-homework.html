Assignment

Write and run ten scripts

  1. Use the exact table and column names shown above.
  2. Complete each task in its own box. Every Run starts from the original data, so begin each script with the DROP ... IF EXISTS housekeeping it asks for — that habit is what makes real scripts re-runnable.
  3. Include every requested SELECT so the result can be graded.
  4. Task 10 is supposed to end with an error. The error message printed under your results is part of your evidence — do not remove the failing statement.

Put a calculation inside a view

Create a view named ITEM_VALUE over ITEM that shows ITEM_ID, DESCRIPTION, ON_HAND, PRICE, and ROUND(ON_HAND * PRICE, 2) AS STOCK_VALUE. Then query the view like a table: select every column for rows where STOCK_VALUE is at least 520, ordered by STOCK_VALUE from highest to lowest. Include the housekeeping DROP VIEW IF EXISTS first. In Module 6 you froze this same calculation into a table with CREATE TABLE ... AS SELECT, and the copy went stale the moment anything changed — a view is the other choice: same name, same columns, but the calculation stays live.

Make an index earn its keep

Start with DROP INDEX IF EXISTS CUSTOMER_INDEX1. Run EXPLAIN QUERY PLAN on this query: select CUSTOMER_NUM and CUSTOMER_NAME from CUSTOMER where CITY = 'Seabrook' ordered by CUSTOMER_NAME — the plan says SCAN, meaning every row is read. Create a composite index named CUSTOMER_INDEX1 on CUSTOMER (CITY, CUSTOMER_NAME), run the same EXPLAIN QUERY PLAN again, and watch it become SEARCH ... USING INDEX. End by listing name and tbl_name from sqlite_master where type = 'index' and the name does not start with sqlite_.

10

Let a constraint do its job

Start with DROP TABLE IF EXISTS CREDIT_CHANGE. Create a table named CREDIT_CHANGE with: CHANGE_ID INTEGER PRIMARY KEY; CUSTOMER_NUM CHAR(4) NOT NULL; NEW_LIMIT DECIMAL(9,2) NOT NULL; a named constraint CONSTRAINT LIMIT_RANGE CHECK (NEW_LIMIT BETWEEN 1000 AND 15000); and a table-level FOREIGN KEY (CUSTOMER_NUM) REFERENCES CUSTOMER(CUSTOMER_NUM). Insert one valid request — customer 2135, new limit 9000.00, naming just the two target columns: in SQLite an INTEGER PRIMARY KEY fills itself in when you leave it out of the INSERT. Select the table to show the row landed. Then, as the last statement, try to insert a request for customer 2110 with a new limit of 25000.00. The script must stop with a CHECK constraint failed: LIMIT_RANGE error — that error, printed under your one successful row, is the graded evidence that the constraint works.
